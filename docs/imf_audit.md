# IMF numerical and image-processing audit

This audit records source behavior, not measured task benefit. The fixed 28-channel order remains unchanged. The dataset is not rerendered and these findings do not tune scales from validation/test data.

| Stage | Implemented behavior and contract | Audit status / implication |
|---|---|---|
| BGR→YCbCr | `vision.cpp::Impl::prepare` scales BGR8 to `[0,1]`, calls OpenCV `COLOR_BGR2YCrCb`, then publishes Y,Cb,Cr in that order. | Deterministic fixed-range color transform; verify exported planes visually on the one-episode diagnostic, not by scene min/max. |
| Gaussian | Same prepare path applies configurable odd kernel/sigma (default 3, 1.0) before luminance derivatives. | Reused by derivative and dense-flow preparation. Geometry and color are not blurred by this stage. |
| Sobel | `vision.cpp::Impl::derivatives` uses 3×3 Sobel with `/8/255`, `BORDER_REFLECT_101`; output is image-normalized intensity change per working pixel. | Sign follows image x right/y down. Fixed scale is reproducible. Border values use reflection. |
| Magnitude | `cv::magnitude(gx,gy)` reuses the existing derivatives. | Nonnegative and fixed √2 scale/clipping at tensor packing. |
| Dense HOG | `denseHog` uses shared Gx/Gy phase and magnitude, 9 unsigned bins over `[0,π)`, linear interpolation between bins, 32×32 cell assignment, per-cell L2 normalization with `1e-12` floor. | Spatial layout remains aligned. A cell histogram has unit L2 energy when nonempty; empty cells remain zero. This is dense cell HOG rather than block-normalized Dalal–Triggs HOG. |
| Harris | Reuses the dense derivative/structure-tensor path; output is continuous and signed after configured fixed scale, signed square root and clipping in `normalizeChannel`. | The nonlinear scale makes numeric magnitude an empirical descriptor rather than a directly physical response; do not interpret it as calibrated corner probability. |
| Canny | `boundaries` converts/reuses shared derivatives for Canny and uses configurable thresholds (defaults 20/60 in raw 8-bit gradient units). `ContourMap` rasterizes contours found from that edge result. | Canny/contours are binary and spatially registered. They overlap information by design; only ablation/runtime measurements can justify removing either. |
| Chroma gradients | `analyticalSpatial` runs separate Sobel derivatives on Cb/Cr planes with scale 1/8, then magnitude. | The separate derivatives are mathematically necessary because luminance gradients cannot recover chroma transitions. Fixed bounded scaling at packing. |
| Dense flow | `denseMotion` runs Farnebäck on previous/current prepared luminance. `scatterDenseFlow` moves each previous-pixel vector to its current endpoint; output therefore aligns with the current-frame feature grid. | U/V are current-minus-previous image displacement (working pixels/frame), fixed `flow_scale_px` normalization. Missing previous support has zero data and invalid mask. |
| Sparse flow / geometry | Existing sparse tracker retains IDs/correspondences; relative pose, triangulation, cheirality/reprojection/parallax filters and a bounded local colored map stay in the C++ path. | Sparse tracking supplies geometry correspondence; dense flow supplies spatial channels. Monocular scale remains explicitly invalid absent metric support. |
| Depth projection | C++ terrain/point geometry projects into current camera coordinates with current resized intrinsics; each plane has a support mask. Tensor Depth stores optical-axis depth divided by configured depth scale. | Python metric attention back-projects only valid IMF depth and scaled intrinsics into OpenCV camera axes; no target-only simulator depth is an inference input. |
| Depth derivatives | `geometry.cpp::detail::depthGradients` applies 3×3 Sobel `/8`, multiplies horizontal/vertical derivative by corresponding feature-grid focal length and divides by depth, then `normalizeChannel` divides by `depth_gradient_scale` and clips signed. A 3×3-eroded depth support mask is required. | This is a dimensionless relative depth gradient over normalized image coordinates, not metres per grid step. Direction is image x right/y down. |
| Slope / roughness | Existing terrain surface analysis derives slope and roughness from the interpolated local terrain grid; tensor scaling uses `2/π` for slope and configured metres for roughness. | Physical meaning depends on successful metric reconstruction and grid support. No valid terrain means invalid, not a fabricated flat surface. |
| Geometry confidence | `terrainConfidence` combines map-point confidence/age, motion quality, support and nearest measured-point distance; it is bounded before projection. | A heuristic support score, not calibrated probability or covariance. Covariance is separately approximated by Python from pixel/depth noise and configured pose-support model. |
| Validity | `reduceChannel` area-reduces value and support, marks valid when at least half the contributing source support is valid, divides by support, and zeros unsupported outputs. Packing preserves separate masks. | A valid zero is a measurement; invalid zero is missing. Feature tests enforce binary masks and documented numeric bounds. |

## Learned fusion and known overlaps

The normalization spec (`data/configs/feature_spec.json`) describes expected ranges, units, fixed scaling and validity semantics. The neural family adapter receives individually masked channels and masks, then local depthwise refinement. It does not z-score the mixed physical families.

Theoretical overlap remains in gradients/magnitude/HOG/Harris and edges/contours. The source reuses derivatives and edge maps, so this overlap is not identical to duplicate full extraction. HOG and Harris may still cost compute and add little task value; answer that empirically through representation ablation paired with the C++ family-disabled timing. No channel has been removed based on intuition.

## Validation boundary

Automated tests cover feature range/mask contracts, metric back-projection, visibility states, covariance propagation and attention. The existing C++ tests cover analytical feature and geometry behavior. This revision has not run the locked test split, rerendered the dataset, or measured a new full-dataset quality/runtime result. Development-machine one-episode extraction and current automated tests are diagnostics only. See [benchmarking.md](benchmarking.md) for existing measurements and what remains unmeasured.
