# Persistent uncertainty-aware semantic local map

`common/mapping/semantic_map.py` stores bounded local metric entities rather than point-cloud activations. Schema `imagination-semantic-map-v3` records entity ID, map-frame XYZ, optional 3×3 position covariance in m² and its validity/source, class probabilities, Dirichlet evidence, semantic confidence, observation count, timestamps, extent, attributes, configured semantic-association groups and bounded source-observation references. The map limits entity count, age and local radius. It stores no neural feature activations.

## Position uncertainty

Detection pixel and depth uncertainty is propagated through OpenCV pinhole back-projection with a first-order Jacobian (`uncertainty.py::pixel_depth_covariance`). Camera-to-map rotation and a six-dimensional pose covariance propagate through `Σ_y = JΣ_xJᵀ`. The C++ pose estimator currently does not expose a calibrated covariance. `approximate_pose_covariance` therefore derives a configurable heuristic from measurable IMF support and labels its provenance as approximate; it must not be reported as calibrated uncertainty. Covariance validation checks finite values, symmetry and positive semidefiniteness, then floors near-zero eigenvalues for stable solves. When an observation has no valid covariance, it no longer erases a previously supported entity covariance.

## Association and semantic evidence

The spatial hash/voxel preselection and Euclidean radius gate bound the candidate set. Semantic compatibility is measured as shared posterior mass (`1 − total-variation distance`), with a configurable minimum. Configured surface groups, currently `background/grass/track`, also permit geometry-supported class contradictions to reach Bayesian fusion. Object-class incompatibilities remain gated. This lets a track-to-grass flip reduce track evidence rather than create a spatial duplicate. During relational construction, posterior mass above `semantic_rule_probability_threshold` for a restricted class contributes conservatively to safety geometry even if that class is not the current argmax. The map records semantic-gating rejects. If both positions have valid covariance, the final spatial gate uses squared Mahalanobis distance with a linear solve over `Σ_i + Σ_j`; otherwise it records a Euclidean fallback. The old Euclidean mode remains selectable for the association ablation. Duplicate/incorrect-merge and runtime comparisons still require simulator-truth evaluation.

Semantic observations accumulate bounded Dirichlet-style evidence, weighted by prediction confidence and a temporal-correlation discount. Evidence can decay by age when configured and is capped to prevent certainty growth without bound. Low total evidence or a diffuse class belief yields `unknown`. Arithmetic probability averaging is retained only as an explicit reference mode. The resulting belief is an evidential representation, not a calibrated posterior guarantee. A nonzero posterior-overlap threshold lets credible contradictory soft predictions reduce or revise a class belief; disjoint high-confidence classes remain separate.

## Coordinate frames and visibility

Map entities and 2-D projection use actual map-frame XYZ. Candidate tokens carry a separate egocentric representation. In the configured ground-navigation convention, map-to-ego subtracts UAV map position and rotates only the horizontal plane by yaw: `+x` forward, `+y` left, `+z` up. Roll/pitch do not rotate the ground surface. This is a yaw-aligned 2.5-D frame, not the aircraft body frame. Missing yaw falls back to map-aligned values and exposes `orientation_valid=0`. `map_to_egocentric` and its inverse are tested for round-trip and yaw invariance.

Projection transforms map XYZ through the inverse current camera-to-map pose, then uses the scaled intrinsics and OpenCV camera axes. Visibility is deterministic and uses no simulator truth: behind camera, outside FOV, occluded by measured IMF depth, depth inconsistent, visible, or unknown when support is missing. Candidate context tokens are excluded from attention unless projection is in-FOV and visibility permits it. The no-visibility ablation retains only geometric front-of-camera/FOV projection and bypasses the depth occlusion test.

## Relational representation

`common/registry.py` defines 30 global relation values and 40 candidate values. Global quantities separate geometry support, semantic confidence, position uncertainty, semantic entropy, visible fraction, evidence support and freshness. Candidate tokens are capped at 32 and sorted by deterministic priority/importance. They contain egocentric XYZ, distance/bearing, type, posterior confidence, extent, terrain attributes, candidate-centered free radius, track/restricted and nearest-obstacle clearance, obstacle/cone density in named 2 m neighborhoods (entities/m²), drifted clearance/landing margin, age, uncertainty, entropy, evidence, six one-hot visibility flags, orientation validity and importance. Each candidate value has an independent validity bit; the neural encoder sees masked values concatenated with those bits.

Clearances are candidate-centered point-to-disc approximations using mapped extents and combined 2σ covariance margins where available; they are not polygon-exact track-boundary distances. A no-land rule alone classifies an object as an obstacle; restricted-zone clearance uses explicit `restricted_zone: true` or `fly_allowed: false`, keeping cones/rocks in obstacle clearance rather than turning them into region boundaries. Free radius is valid only for landing/terrain candidates with both obstacle and restricted-zone evidence. Drifted clearance shifts each candidate in the map frame by the constant-velocity drift estimate; the learned relation vector rotates that drift into the same yaw-aligned ego frame as candidate tokens. Track and grass samples can be merged into coarse region tokens with aggregate extent, support and covariance so reducing redundant tokens does not simply discard all ground coverage. Merged `xyz_m` remains absolute local-map XYZ; its token displacement is separately egocentric. Safety/restricted classes receive deterministic priority before the 32-token cap. Candidate order is not used as a persistent map identifier.

High-confidence POIs, model-predicted high-hazard regions, and high-uncertainty entities near a proposed landing region are also promoted before ordinary tokens. Their thresholds are configurable in `data/configs/semantic_rules.yaml`; if critical entities alone exceed the fixed 32-token capacity, deterministic importance/distance ordering resolves that limit. Candidate free-space and drift clearances separately account for configured restricted zones and obstacles, using the same point-to-disc approximation. Current-view visibility gates projected spatial context, while nonvisible persistent entities remain available to map relations and candidate safety geometry.

## Causal predicted map

`OnlinePerceptionMap.process` calculates current relational inputs from the prior map, runs current-frame inference, and only then inserts current model predictions. The primary mode accepts `source="predicted"`; the separate oracle mode accepts `source="oracle"` only for diagnostics. Simulator masks and target-only depth are supervision/evaluation inputs and never seed the deployed map. When metric depth or pose is unavailable, the 2-D observation may be kept unresolved; no XYZ is fabricated.

The map supplies known geometry and evidence accumulation to the learned model. It does not make landing decisions by itself. Candidate verdict heads receive masked candidate-local geometry plus the same separately encoded state and 30-value relation context as the global scene head. The Transformer combines these known values with visual evidence into scene/candidate verdicts. Map-token context uses independent pointwise K/V projections, not convolution over arbitrary candidate order, and is gated for current-view spatial attention by visibility. Persistent nonvisible entities continue to contribute to deterministic map relations and candidate safety calculations. The model receives at most 32 projected prior-map candidates, never an unbounded point cloud or long raw frame history.

Schema-v1 maps migrate explicitly: old position covariance/evidence remain unavailable, and existing class probabilities become a one-unit legacy prior rather than invented historical evidence. Schema-v2 maps remain loadable and default to no configured semantic-association groups unless supplied by the caller; schema-v3 persists the group selection. Checkpoints also carry the model and semantic-fusion contract versions and reject incompatible old architecture state.
